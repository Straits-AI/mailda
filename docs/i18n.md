# Interface languages

How the interface's words are held, chosen and checked (Blueprint §29, ADR 46). English (`en`) is the source
and the only language offered to viewers. Simplified Chinese (`zh-Hans`) is a **preview**: its catalog is
complete for every migrated screen, and nobody sees it unless they ask for it by address.

What stays English whatever the viewer chooses, permanently: everything a program reads. The API's bodies and
error messages, `mailda` and its `--json`, doctor's text, MCP, the Agent Skill, the SDK, the operational log,
audit keys and SMTP replies are byte-stable for the agents and gates that parse them (`mailda deploy` reads
doctor's verdict from its first line). The interface shows the Node's own English inside `<NodeWords>`, marked
`lang="en"`. The CLI's interactive prose is deferred rather than forbidden: it is translated when an operator
asks for it, chosen by `MAILDA_LANG`, then `LC_ALL`, then `LANG`.

The sender's content is never translated, and neither the message frame nor a plain-text body takes the
interface's language. Each keeps the message's own: the sanitiser keeps a sender's `lang` and `dir` on every
element it keeps (`bdo` and `bdi` among them), and the frame's root carries `data-script` (`sc`, `tc`, `jp`: which
glyph forms Han is drawn in, never `lang`) from what the message says, in order the rendered body's charset (GB2312,
GBK and GB18030 are `sc`, Big5 `tc`, ISO-2022-JP, Shift_JIS and EUC-JP `jp`; never an attachment's), then its
`Content-Language`, then the HTML's own root `lang`, and only then the reader's locale (zh-Hans guesses `sc`,
English guesses nothing). A sender's `lang` on an inner element picks that element's forms over the frame's
(`[lang]:lang(ja)` and its siblings in `frame.css`). A plain-text body is drawn in the shell's document, so its
`<pre>` carries `lang=""` and the same `data-script`, with the frame's families (`scriptFamily` in
`apps/node/worker/src/theme.ts`). The body route returns the message's answer as `script`
(`apps/node/worker/src/render/script.ts`), a string on the wire that the reader narrows to `BODY_SCRIPTS`. A UTF-8
message that says none of these says nothing, and an English reader then gets the platform's own choice.

## Where the words live

```
apps/node/worker/src/i18n/
  locales.ts         LOCALES: tag, direction, endonym, preview. OFFERED: the non-preview ones.
  format.ts          the runtime, pure: Message, Plural, Params, Text, parts(), text(), negotiate(), resolveLocale()
  areas.ts           AREAS: each catalog area and the key prefixes it owns
  en/<area>.ts       the source words, one module per area; their literals are the type
  zh-Hans/<area>.ts  each area's twin, typed Twin<typeof en area>
  en/index.ts        preauth, and app = every other area joined (and zh-Hans/index.ts)
  catalog.ts         Catalog, Key, Source, Twin, CATALOGS
  preauth.ts         every locale's preauth table, and nothing else (what /app/locale.js bundles)
  served.ts          each locale's app table as a module, and its content-tagged URL
  glossary.ts        CONCEPTS, NEVER, NEGATES
apps/node/worker/src/client/locale.ts        the browser half: bootLocale, install, loadApp, t, rich
apps/node/worker/src/client/app/format.ts    every date, time and number the interface formats
apps/node/worker/src/client/app/words.tsx    <NodeWords>, marked(), sentence()
apps/node/worker/src/client/app/title.ts     the per-route document title
apps/node/worker/src/client/app/ui/ime.ts    isComposingKey
apps/node/worker/src/client/app/delivery-words.ts   the words for the tokens /app/delivery.js returns
```

**How the words reach a page.** `scripts/build-client.mjs` builds `src/client/locale.ts` into `/app/locale.js`,
a second entry point beside the shell, with every locale's `preauth` table in it. The framework-free script
imports it first and calls `bootLocale()`, which picks the locale and sets `<html lang>`, `dir`, the title and the
wordmark before anything renders. When somebody signs in, `handOverToShell()` preloads the shell and fetches the
locale's `app` table from `/app/messages/<locale>.<tag>.js` inside the same `try`, so a table that cannot be
fetched shows the "could not be loaded" notice. The tag is computed from the table's text by the build and by the
Worker from the same catalogs, so the URL is `immutable`. An old tag of a known locale, which a sign-in tab left
open across a deploy still names, is a `no-store` 307 to the current table: the old address is never handed new
words, and the sign-in does not fail on a 404. The shell leaves
`/app/locale.js` external, so one module instance holds the one table.

## Adding a string

1. Put the English in the area module of the file you are migrating (`en/inbox.ts` for `inbox.tsx`), under
   that area's prefix: `"inbox.empty": "Nothing here yet."`. A key outside the prefix does not compile.
2. Put its translation under the same key in `zh-Hans/inbox.ts`. A missing or extra key does not compile.
3. Render it: `t("inbox.empty")`, or `t("inbox.count", { n })` for a plural. A misspelt key or parameter does
   not compile. A sentence with an element inside it uses `sentence("key", { who: <strong>{name}</strong> })`,
   so the translation moves the element and cannot add one.
4. Delete the literal, then lower the file's count in `UNMIGRATED` (`apps/node/worker/test/node/untranslated.registry.ts`)
   by what you removed. The test fails until the number matches, in either direction.
5. A literal the scan flags that is not words (an API path, a storage key, a media query) goes in
   `NOT_PROSE`, under its file, with its reason.

Rules a check cannot see:

- **A key is a concept, not an English phrase.** A change of meaning renames the key, so the translation stops
  compiling and is redone. A wording tweak under the same key is caught only in review.
- **`n` is always the count, and the measure word is inside the message**: `{n} 封邮件`, never `n + " 封"`. Two
  counts are two messages, each a plural on its own `n`, filled into the sentence as parameters
  (`ledgers.collect.done`). `50+` stays `50+`, never 共 50 封 (a page is never a total). A noun passed into a shared
  template brings its own measure word, because the word depends on the noun: `chrome.truncated` is
  `仅显示最新的 {n} {noun}` (a plural on the count shown), and `drafts.noun` is 份草稿, `chrome.notices.noun` 条通知 (F5, below).
- **Closed vocabularies are keyed by their tokens**: `route.${AppRoute}` must have a key for every route, by type.
  A wire token outside the union renders raw, in `<code>` (`shown()` in `delivery-words.ts`). The sending vocabulary is the model: the contract declares
  `SEND_STATES`, `SEND_REASONS`, `DELIVERY_STATES` and `DELIVERY_REASONS` as `as const` lists while the wire stays
  `z.string()`; `en/delivery.ts` `satisfies Record<DeliveryKey, string>` over them, so a token without words, or
  words for no token, does not compile; `/app/delivery.js` decides which token a reader is shown and returns it,
  and `delivery-words.ts` narrows it with `oneOf` before building the key (label at `send.state.<token>`, note at
  `send.state.<token>.note`).
  **Closed vocabularies** (round three, G12): the contract also declares `BUTLER_RUN_STATES`, `BUTLER_VERSION_STATES`,
  `BUTLER_PAUSE_REASONS`, `MATTER_TYPES`, `EXPORT_STATES` and `RATE_BREAKER_NAMES`, and the Node's modules that write
  them use those lists rather than copies of their own (`apps/node/worker/src/butler/record.ts`,
  `apps/node/worker/src/butlers.ts`, `apps/node/worker/src/butler/pause.ts`, `apps/node/worker/src/matters.ts`,
  `apps/node/worker/src/exports.ts`, `apps/node/worker/src/breakers.ts`). Five are keyed the same way
  (`matters.type.*`, `matters.export.*`, `butlers.version.*`, `butlers.pauseReason.*`, `limits.breaker.*`), English
  unchanged; a token outside the list renders raw in `<NodeWords>`. `matters.type.legal_hold` is bound to the
  `legal-hold` row. A Butler run's state is not keyed yet: it is shown inside the Node's own line
  (`trigger_event · state`) and in the dry run's verdict, so it waits for layer 3. Their fifteen Chinese words
  (法律保全, 安全事件, 离职交接, 监管要求; 已申请, 运行中, 已完成, 已中止; 草稿, 已发布, 已被取代; 检测到循环; 发信量, 退信率,
  投诉率) are new since the owner's round three, for the owner to see on the next
  review page; zh-Hans is a preview, which may carry them.
- **Never persist a `t()` string as data** (critic L10). A default a viewer's interface writes into the Node
  (a mailbox name, a label) would become a word every other viewer reads in the writer's language. One
  exception, by design: a reply's quote line (`composer.quote`, "On {date}, {from} wrote:" / "{date}，{from}
  写道：") is written into the mail in its **author's** interface language, as Gmail and Outlook write theirs,
  because it is part of what the author wrote (ADR 46: persisted prose stays in its writer's language). Its date
  is `format.zonedTime`, which carries the offset from UTC (`GMT+08:00`), so a correspondent in another zone does
  not misread the hour. The subject prefixes are not the interface's words: `Re:` and `Fwd:` stay English on the
  wire in every locale, and `replySubject` / `forwardSubject` in `src/client/app/screens/composer.tsx` do not add
  one after a Chinese client's own (`回复：`, `答复：`, `转发：`, either colon).
- **The Node's own English goes through `<NodeWords>`**: an error `message`, a doctor `detail`, a breaker's
  sentence. Only the Node's: a failure's words may instead be this interface's fallback ("this Node answered 503",
  translated), so `api.ts` carries who wrote them (`Said`: `message` and `fromNode`, on `ReadFailure` and on every
  refusal) and a screen shows a failure with `marked(failure)`, which wraps only the Node's. A toast's `text` and
  `<Nothing detail>` take a node for this reason; a sentence with the Node's words inside it is `sentence()` with
  `marked()` as the argument, never `t()` with the words as a string. Per-code interface text for an error waits
  for an `ERROR_CODES` registry in the contract.
- **Formatting goes through `src/client/app/format.ts`.** For an English viewer it formats exactly as before
  locales existed (the browser's default locale). The one table is English's month names (`MONTHS`, for
  `shortTime`, `monthDay` and `recordDay`: `15:09`, `26 Sep`, `26 Sep 2025`), because `Intl`'s short month for September changed
  to "Sept" across ICU versions; another locale asks `Intl` for its own numeric forms (`15:09`, `9月26日`,
  `2025/9/26`). Durations and counts are plurals keyed by the count (`queue.duration.*`), and nothing compares
  formatted text: the Queue's "just now" is decided on the number of milliseconds, never on the words.
- **Two sentences side by side are joined with `t("join.sentence")`**, never a literal `{" "}`: a space in English,
  nothing in Chinese, whose 。 and （ carry their own spacing (G14). The gap after a control or a Latin token is not a
  sentence join and stays a space.
- **Every Enter handler asks `isComposingKey(event.nativeEvent)` first.** An IME's Enter commits a candidate.
  `apps/node/worker/test/node/ime.test.ts` parses the client for every comparison of a `key` with `"Enter"` and
  fails on one whose function does not ask.

## Adding a locale

1. Add it to `LOCALES` with `preview: true`, its direction and its endonym.
2. Create `<tag>/<area>.ts` for every area and `<tag>/index.ts`; add it to `CATALOGS` and `PREAUTH`. Each is a
   compile error until it exists.
3. Add its column to every glossary row. Rows start `proposed`.
4. Review it with `?locale=<tag>`.
5. Take `preview` off when `UNMIGRATED` is empty and every row its keys use is confirmed (below).

## The preview flag

A preview locale is reachable **only** through `?locale=<tag>` in the address: browser negotiation never picks
it, a stored choice naming it is ignored, and Settings > Language does not list it. The flag applies to that page
load, is never stored, and works where the browser refuses storage. Settings says, when it is in force, that the
page is in that language only because its address asks for it. So no viewer who did not ask is shown a screen that
is partly English, and the `lang="en"` wrapping of untranslated components that a shipped partial locale would
need is not built.

`preview` comes off when `UNMIGRATED` is empty, a pseudo-locale render of every route including its error states
finds no English outside `lang="en"` (not built yet), every string the Node supplies on the locale's screens
renders through `marked()` or `<NodeWords>` (the migrated screens do, the reader, the composer, the Queue and the
ledgers since layer 2a, and every React screen since layer 2b; the framework-free scripts still in `UNMIGRATED` render
theirs bare until layer 3 migrates them), and
the glossary rows the locale's keys use are confirmed.

## Choosing a language

Settings > Language lists the offered locales, each in its own language (`endonym`, data rather than
`Intl.DisplayNames`). While English is the only one, it says so. Choosing flushes an open draft, stores the choice
in this browser (`mailda.locale`) and reloads; a draft the Node will not save stops the reload. Where the browser
will not keep the choice, the page reloads with `?locale=` instead and says it will not last. Boot order:
`?locale=`, the stored choice (offered locales only), `navigator.languages` negotiated on language and script over
the offered locales (`zh-TW` is Traditional and matches nothing), then English.

Not built, and the trigger for each: a per-person language on the Node (`users.locale`) and an organisation
default, when the Node first writes a message to a person or somebody asks for the choice to follow them across
browsers. The first frame shows `lang="en"` until the module runs, as the theme does; a cookie mirrored into a
server-rendered `lang` is the upgrade.

## The glossary

`glossary.ts` has one row per **concept**: the word each locale uses, the words it avoids, and the keys bound to
it. "held" is five concepts with five Chinese words; "Mailda" is one (`prose: true`), so any English that names
it must say 淼达 in Chinese. A key bound in `keys` must equal the term (a label, a route name); a key bound in
`sentences` must contain it (Released to the queue, 已放回队列), for a concept whose English word means other things
elsewhere and so cannot be `prose`. An `avoid` list applies only to its concept's keys. `NEVER` is for phrases wrong in
every position (发送成功, 投递成功, 送达, 必达, 使命必达, 秒达, 您, 废纸篓); a key whose text honestly negates one declares it in
`NEGATES`, and a person reads that key. 送达 joined in layer 2b and the owner confirmed it in round three.

**Every row is `proposed` until the owner confirms it.** A confirmed row carries `{ confirmedBy, record }`, where
`record` links the owner's own written confirmation and says when it was made (a pull request review, an issue
comment, or a decision the owner recorded on a review page), and nobody writes one for somebody else. A locale that
is not a preview may not ship a key bound to a proposed row. The check cannot tell who typed the field, so **the real
gate is the owner's approval of the pull request**.

### Register (zh-Hans)

- 你, not 您; 本节点, not 我们. The English speaks as the Node, not as a vendor.
- Full-width punctuation in sentences (，。：；？！) and “ ” quotes. Checked.
- One space between Han and a Latin letter or digit: `3 封邮件`, `Worker 与密钥`. Checked in the catalog (T2), and
  made by the runtime where a filled value meets a Han template (`{name}已发布` with `lead-response` is
  `lead-response 已发布`), which no catalog check can see; never inside the value.
- Identifiers stay Latin and in mono: relation tokens, `E_` codes, budget names, CLI verbs, header names, `.eml`.
- Han is not broken mid-word where a column is narrow: under `:root:lang(zh)`, `thead th` (layer 2a) and the buttons
  and links in a table cell (`td button, td a`, layer 2b) keep words whole (`word-break: keep-all`), since a phone
  width otherwise stacked 发布 and 恢复发信 one character per line. Text cells still wrap per character, so every table
  cell is at least `4em` wide under `:root:lang(zh)` (G16, round three): four Han characters, a presentation constant,
  intended so that 已启用 or 生效中 · v1 holds one line and a sentence wraps inside its column rather than down one character's width.

### Brand

The brand is **淼达** in the zh-Hans interface: the shell's wordmark and the title (`{screen} · 淼达`). English
shows Mailda only. The sign-in and claim lockup (淼达 with a secondary Mailda) is layer 3. `mailda` stays in every
