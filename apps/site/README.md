# mailda.site

The landing page and the documentation, one static site, one Worker with assets.

`/` is the README's Status table laid out as a `mailda doctor` report. `src/gaps.ts` reads the table, `src/components/Landing.astro` lays it out. The `ok` rows link to the doc that earns them. The `warn` rows are the README's own words.

`/zh-cn/` is the same page in Simplified Chinese (`src/pages/zh-cn/index.astro`), under the mark 淼达 with a secondary Mailda, in the app's glossary words and register (`docs/i18n.md`). Its words, and the English page's, come from one table per locale in `src/landing-words.ts`; the build throws on a key one table has and the other does not, or an empty value, since `astro build` does not type-check. The README's `warn` rows stay English on the Chinese page, marked `lang="en"` under a heading that says so. Both pages carry a switch (English / 简体中文, plain links) and `hreflang` alternates. On `/`, a small inline script sends a first visit whose browser asks for Simplified Chinese before English (`zh`, `zh-CN`, `zh-SG`, `zh-MY`, `zh-Hans`; not `zh-TW`, `zh-HK` or `zh-MO`, as the Node negotiates) to `/zh-cn/`, unless the visitor chose English on the switch (kept in `localStorage` as `mailda.locale`), came from a page of this site (so the switch back works where storage is refused), or is automation or a crawler. `/zh-cn/` has no such script, so the two cannot loop.

Both landing pages play videos: the explainer in the page's language under the hero, and five more (English on both pages) under *See it work*. `src/videos.json` names each one, its poster, its length, its sha256 and the words on its screen, which are written out under it because the videos have music and no voice. The files are not in git, since the repository is how every Node installs and updates: they are assets of the release `src/videos.json` names, rendered outside this repository. `pnpm run deploy` runs `scripts/fetch-videos.mjs` after the build, which downloads each one into `.videos/` (gitignored, so a second deploy fetches nothing), refuses any file whose sha256 is not the recorded one, and copies them into `dist/videos/`, so the site serves its own copies and nothing loads from another origin. The build stays offline, so `pnpm test` and CI never download them. Each player has `preload="none"`: a page loads its posters and nothing more until a video is played. To change a video, upload the new file to a release and record its name and sha256 in `src/videos.json`; to build a deploy before the release is published, put the files in `.videos/` by hand.

`/docs/*` is `README.md`, `AGENTS.md`, `docs/*.md` and `docs/receipts/*.md`. `scripts/generate-docs.mjs` renders them into `src/content/docs/docs/` (gitignored) on every build, and shows a receipt's frontmatter as the record instead of swallowing it as page metadata.

`/zh-cn/docs/*` is Starlight's `zh-cn` locale (`lang` zh-Hans): its own Chinese menus, search and navigation, the sidebar's groups in the glossary's words (产品, 运维节点, 测量记录), and for most pages the English page as Starlight's fallback, its body marked `lang="en"` under the notice 此内容尚不支持你的语言。 A doc with a translation in `docs/zh-cn/` (`docs/cloudflare-settings.md`, and the runbook part of `docs/disaster-recovery.md`) is rendered in Chinese at its English page's path instead, its links kept inside `/zh-cn/`, under a note that it is a translation and the English is the authority, and, when it covers only the English's opening part, a closing note linking the rest. Each translation records the SHA-256 of the English it covers (the whole file, or the part before `translated_until`), and `test/translations.test.mjs` fails when that English has moved since, naming both files: update the translation or remove it (`docs/i18n.md`, *Doc translations*). Nothing else is copied to make these pages. Starlight finds its built-in words by stripping a region subtag from `lang`, which turns zh-Hans into nothing it knows, so the generator also copies Starlight's own zh-CN translations into `src/content/i18n/` under the zh-Hans tag (gitignored).

Every claim on the site comes from the repository's Markdown, so the site cannot say something the README does not. `test/build.test.mjs` fails the build if a doc has no page in either language, a status row is missing from either landing page, the Chinese page uses a phrase in the glossary's `NEVER` list (imported from `apps/node/worker/src/i18n/glossary.ts`, which is why the test runs under `--experimental-strip-types`: CI's Node is 22, per `.nvmrc`) or shows an identifier bare beside Han rather than in `<code>`, the English page's markup moves from `test/golden/landing.en.html` (`UPDATE_GOLDEN=1 node --test` rewrites it, for a change that means to), a landing link points at no page (a `/videos/` file counts when `src/videos.json` names it), a landing page shows a video `src/videos.json` does not give it or lacks one it does, or a player loads before a press, the `hreflang` alternates or the Chinese docs' notice go missing, a translated doc's page is missing, marked English or links English pages other than its original, the first-visit redirect decides any case wrongly (it is run under `node:vm`), or anything loads from another origin. `test/translations.test.mjs` reads the repository rather than the build: a translation whose English has changed since its recorded hash, or whose code blocks, links, inline code, tables or headings differ from its English's, or that uses a `NEVER` phrase or breaks the zh-Hans register, fails. Turbo's cache for this package's tests keys on the README, `AGENTS.md`, `docs/` and the glossary too (`turbo.json`), so an edit there alone re-runs them.

```sh
pnpm dev                       # astro dev, regenerates docs first
pnpm test                      # build, then the checks above
CLOUDFLARE_ACCOUNT_ID=… pnpm run deploy   # build, fetch the videos, wrangler deploy: mailda.site and www.mailda.site.
                                         # `run`, because bare `pnpm deploy` is pnpm's own workspace command and answers
                                         # ERR_PNPM_NOTHING_TO_DEPLOY without ever reaching wrangler (24 September 2026)
```

The fonts are copied from `apps/node/worker/fonts`, the mark from `brand.ts`. The palette in `src/styles/site.css` is the Node's, mapped onto Starlight's tokens.
